# Choose a durable form

Honor an explicit destination that satisfies authorization and validation.
Otherwise choose by the information's role:

| Information | Destination |
| --- | --- |
| Repeatable typed records | An existing Active Dataset with a matching schema |
| Reusable concepts, claims, decisions, policies, hypotheses or open questions | OKF Knowledge |
| Original bytes, layout, or a complete formatted artifact | An ordinary Document |
| An example for producing later Documents | A Document Template, never the output itself |
| Accounts, contacts and interactions | CRM |
| Operational progress, assignments and deadlines | Cases and ToDos |
| Material still being gathered, questioned and decided together | A canvas: a collaborative thinking surface, not a durable Knowledge store; distill it, then a person publishes to Knowledge |

For record-shaped work, use the Datasets skill to discover plausible authorized
Datasets, inspect their description and useWhen, and read the selected schema.
Do not query records merely to design a procedure. Do not infer fields, upsert
intent, or create or revise a Dataset implicitly. If no Active Dataset fits,
ask whether Dataset design or another destination is intended.

Use OKF when meaning and relationships are primary, not to disguise a table as
concepts. An ordinary source Document may also yield linked OKF; its ingestion
workflow owns that assessment and bounded CRM contact extraction.

Ask one concise question if the choice materially changes structure or
provenance. Stored guidance alone never triggers discovery or persistence.
If necessary discovery tools are absent, explain which same-organization
binding is needed; never silently broaden a Realm or read-only session.
